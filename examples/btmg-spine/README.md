# BTMG · 四足机械犬 / Spine PRO 4.3.23

使用提供的 `btmg.json` 与七张原始透明 PNG，制作适合手机小尺寸观看的夸张动作。强调预备、冲击、回弹、头颈与尾部延迟，而非所有部位一起匀速摆动。原画朝左，移动为原地对角四足循环。

## 本地 Spine 导入

1. 完整解压动画 ZIP，进入同时包含 `btmg-4.3.json` 和 `images` 的文件夹。
2. 打开 **Spine PRO 4.3.23 → 导入数据 / Import Data**，选择 `btmg-4.3.json`，比例为 **1**。这是骨骼数据，不是原生 `.spine` 工程。
3. 图片缺失时，将图片目录指向同级 **`images`**。
4. 切到 Animate 模式检查五个动作。`stand` 和 `move` 循环；`attack`、`hit`、`dead` 通常单次播放。
5. 另存为同目录的 `btmg.spine`，保留图片相对路径，再用本地 Spine 导出游戏所需图集与 JSON/二进制。

无需启动角色拆分网页或 Python 服务。预览可直接双击 `preview.html`；若浏览器禁止 `file://`，可跳过预览直接导入 Spine，或在素材文件夹运行 `py -3.12 -m http.server 8001 --bind 127.0.0.1` 后访问 `http://127.0.0.1:8001/preview.html`。GIF 的云端检查通过临时 HTTP 服务进行，不声称绕过浏览器策略验证了本地文件打开。

## 动作（名称严格对应）

| 名称 | 时长 | 内容 |
| --- | --- | --- |
| `stand` | 2.4 秒 | 稳定四脚支撑，头颈呼吸摆动、牙部轻动、尾部延迟；循环 |
| `dead` | 1.6 秒 | 惊顿压身、四肢折收、头身下沉、尾部松落与短回弹，稳定末姿 |
| `hit` | 0.5 秒 | 快速后仰与头颈甩动，尾部跟随、反向缓冲、恢复 |
| `attack` | 1.0 秒 | **后撤压身 → 张口蓄力 → 前冲咬合 → 拉扯回弹 → 回收** |
| `move` | 0.8 秒 | 对角四肢交替抬脚、屈伸、压重心与尾部跟随；**原地循环** |

所有关键帧以 30 FPS 烘焙。`stand`、`move` 首尾世界骨骼变换一致；`move` 的 root 无水平/垂直平移，实际移动由游戏代码控制。动画交叉混合可从待机/移动 0.1～0.15 秒开始尝试，不要在咬合重音前用过长混合稀释冲击。

攻击的前冲由髋、胸、头颈局部位移与四肢姿态表现，结束后回到设置姿态。它不会自动驱动游戏碰撞体或角色移动组件；如果玩法需要真实位移，请在引擎控制。原画没有独立下颌图层，所以张口/咬合是两侧牙区的加权网格开合，**没有新绘制下颌或补出隐藏口腔**。

## 骨骼与网格

- 共 **22 根骨骼、7 个加权网格附件**，需要 Spine PRO。
- 躯干在胸/髋之间平滑变形，四肢各有上段、下段、爪部控制，保留原图连续像素，避免切片关节裂缝。
- 头部主区与两侧牙区独立加权，尾部有根部/末梢两级跟随。
- 四足轨迹通过两段骨骼求解预先烘焙，没有额外的运行时 IK 约束。爪部支撑朝向独立补偿；移动按“近前肢+远后肢 / 远前肢+近后肢”两组交替。
- 原画前后脚的参考高度存在透视差，保留这些原始高度，不把远侧脚强行拉到近侧地面线。
- 修正了角度跨过 ±180° 时可能产生的 360° 插值转圈；并用 60 Hz（含关键帧之间）姿态检查。

`source/photoshop.json` 保留原始 PS 图层数据结构，只把 E 盘绝对路径改成相对路径。`source/image-sha256.json` 可核对七张原始 PNG：**图片字节和 Alpha 均未修改**，尾部原图最大 Alpha 为 254，也原样保留。图层名和设置姿态遮挡顺序保持一致。

脚底参考原点为原始 PS 坐标 `[310, -440]`。`rig-config.json` 保存源坐标中的骨骼枢轴与关节链，单位为像素，X 向右、Y 向上。骨骼和权重是动画初稿，建议在本地检查大幅动作时的金属关节、爪部交叠与牙区形变；不是物理模拟或保证所有动画混合都无穿插。

## 事件与游戏对接

- `bite_hit`：攻击第 **12 帧 / 0.4 秒**，字符串为 `bite_point`。可以参考该骨骼的世界位置进行咬合判定、音效或特效。
- `impact`：受击第 3 帧 / 0.1 秒。
- `footstep`：移动 0.4 秒、0.8 秒，分别为两组对角落脚的时间标记。
- `death_end`：死亡 1.4 秒。

这些事件只是标记，不包含伤害、碰撞、声音或 AI 逻辑。死亡末姿保持，游戏播放应取消循环。

## 预览与验证范围

`previews/` 包含五个普通 GIF、五个角色约 128 px 高的手机预览、关键帧总览和骨骼图。手机预览全部循环方便对比；死亡在游戏里仍单次播放。GIF 由项目软件渲染器生成，**不是 Spine 桌面视窗截图**。

已用官方 `@esotericsoftware/spine-core@4.3.13` 加载并在 60 Hz 下应用五个动作，共 **383 个姿态**，包括 30 FPS 关键帧之间的时刻。每个姿态检查全部骨骼/网格顶点有限值，并将世界骨骼矩阵及每八个网格顶点（含末顶点）的抽样记录与预览计算比对。报告为 `runtime-validation.json`，含输入 JSON 哈希。

这里没有可操作的 Spine 桌面程序，**未实机验证本机 Spine PRO 4.3.23 编辑器导入**，未生成原生 `.spine` 工程。请导入后检查并另存，不要覆盖你已经手工调整好的旧工程。

## 可选开发重建（需要完整仓库）

导入本地 Spine 不需要 Python。仅修改生成规则或运行测试时需要完整仓库及 `requirements.txt`：

```bat
.venv\Scripts\python.exe tools\build_btmg_spine.py
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

生成脚本覆盖本目录的生成数据和预览，不修改原始 PNG。开发版官方运行库检查：

```bat
npm install --no-save --package-lock=false @esotericsoftware/spine-core@4.3.13
node tests/validate_btmg43.mjs
```

这不是使用动画包的前置条件。修改生成 JSON 后应更新运行库报告，测试会拒绝过期报告。
