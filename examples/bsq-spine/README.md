# BSQ · 毒囊怪物 / Spine 4.3.23 动画包

本包根据提供的 `bsq.json` 和六张透明 PNG 制作，按手机小尺寸清楚、自然且适度夸张的方向，加强预备、主动作、回弹与毒囊延迟跟随。默认朝右，移动为原地循环。

## 文件与本地导入

- **`bsq-4.3.json`：主版本，Spine PRO 使用。** 16 根骨骼、连续加权躯干/腿部网格、六个角色动画。你截图中的 Spine PRO 4.3.23 支持此功能。
- **`bsq-regions-4.3.json`：纯图片兼容版本。** 动作名称相同，但移动简化为原地重心摆动，没有分腿弯曲；一般不需要导入这份。
- **`bullet-4.3.json`：独立毒液子弹。** 动作仅为 `bullet`，与角色分开生成和播放。
- `images/`：六张未改动的原始 PNG，以及本次制作的 `fx/` 毒液素材。
- `preview.html`：角色动作、手机尺寸及子弹的 GIF 预览；无需启动角色拆分网页。
- `source/`、`rig-config.json`、`runtime-validation.json`：原始 PS 数据的可移植副本、绑定配置和验证报告。

解压后在本地 Spine 4.3.23 选择 **导入数据 / Import Data**，选取 `bsq-4.3.json`，比例设为 **1**。不要把它当作 `.spine` 工程直接“打开”。图片缺失时把图片目录指向本目录的 `images`，然后切换 Animate 模式查看动作，并另存本目录下的 `bsq.spine`。独立子弹以同样方式将 `bullet-4.3.json` 导入另一工程，保存为 `bullet.spine`。

两份 JSON 都以同级 `images` 为图片目录；保存工程到其他位置时需重新指定图片路径。包内没有 `.atlas`，编辑器直接使用分离 PNG；最终游戏图集和运行时数据请用本地 Spine 导出。

## 动作名称（严格按要求）

| 名称 | 时长 | 表现与循环 |
| --- | --- | --- |
| `stand` | 2.4 秒 | 头身呼吸、毒囊摇摆与膨缩、手臂轻摆；循环 |
| `dead` | 1.6 秒 | 失衡预备、向前侧倒、毒囊回弹，保持末帧；不循环 |
| `hit` | 0.5 秒 | 快速后仰、头部延迟、手臂震动、反向缓冲；不循环 |
| `attack_1` | 0.9 秒 | 手臂回收蓄力、向前抓击、停顿和回收；通常不循环 |
| `attack_2` | 1.1 秒 | 毒囊鼓起、头部后仰蓄力、前探喷吐、回弹；通常不循环 |
| `move` | 1.0 秒 | 双腿交替抬脚/弯曲、压低重心、头囊跟随；**原地循环** |
| `bullet` | 0.4 秒 | 独立子弹的毒液伸缩、尾迹与小液滴摆动；循环 |

`stand`、`move` 和 `bullet` 首尾骨骼变换一致。角色 `move` 的 root 不包含水平位移；游戏代码控制角色实际移动。近战和喷吐恢复到设置姿态，死亡保持稳定末帧。游戏中切换待机/移动可从 0.1～0.15 秒混合开始调节，攻击命中帧和死亡按玩法安排混合时机。

近战抓击的前臂在伸到前方时通过绘制顺序动画移到头部前面，避免被大头遮住。肩肘有轻微卡通拉伸，原始图层位置和图片本身不变。

## 独立毒液如何发射

角色喷吐动画里包含口部喷溅短特效，但**真正的飞行子弹是另一个骨骼**，不依赖角色的子骨骼移动。

1. 播放角色 `attack_2`。
2. 在 **`spawn_bullet` 事件**（第 12 帧，0.4 秒）生成独立子弹实例，加载 `bullet-4.3.json` 并循环播放 `bullet`。
3. 事件字符串为 `bullet`，浮点参数为 **96**。取角色 `mouth` 骨骼的局部点 `[96, 0]`，转换到世界坐标，作为发射位置；这样包含角色缩放、朝向与头部动作。
4. 方向为 `mouth` 局部 +X 轴变换后的世界方向。让子弹按游戏速度沿该方向移动；命中、伤害、销毁、音效由游戏代码处理。

`bullet` 的 root 始终在原点，没有把飞行距离烘焙进动画，便于复用和控制速度。GIF 中的飞行平移仅是预览示范，不是动画文件自动实现的游戏逻辑。

其他事件：`claw_hit` 在第 11 帧（约 0.366667 秒），位置参考 `claw_tip` 骨骼；`impact` 表示受击重音；`death_end` 在 1.4 秒；`footstep` 在 0.5、1.0 秒分别标记两次落脚。事件本身不会实现碰撞或扣血。

## 原图与绑定

原始素材：`bao` 毒囊、`tou` 头部、`shenti` 躯干/双腿、`zuobi` 后侧整臂、`yougebo` 前侧上臂、`youshoubi` 前侧前臂和爪。沿用原始文件名和设置姿态遮挡顺序。图片 SHA-256 见 `source/image-sha256.json`，六张 PNG 内容未改动。

原图坐标的脚底参考点 `[450, -992]` 移为新骨骼原点。主版本使用原始 `shenti.png` 的连续网格并在身体、髋、大腿、小腿、脚之间平滑分配权重；没有切出可见裂缝，也没有补绘任何遮挡区域。移动使用预计算的两段腿部求解与平滑足部轨迹，烘焙成普通旋转关键帧，不依赖额外 IK 约束。不是严格物理步态，原始透视、脚尖形状或大幅混合仍建议在 Spine 中微调。

毒液、尾迹、液滴和口部喷溅为这次程序绘制的 2D 特效，非原图恢复，使用透明 PNG。没有生成爆炸、命中毒雾、音频或伤害逻辑。

## 验证范围

已使用官方 `@esotericsoftware/spine-core@4.3.13` 实际加载主版本、兼容版本和独立子弹；检查所有动作名称、世界骨骼变换、网格顶点、前臂绘制顺序与喷吐特效时序。主角色 231 个姿态，兼容角色 231 个姿态，子弹 13 个姿态，共 **475 个姿态采样**。预览计算与这些运行库采样逐项比较。

这里没有可操作的 Spine 桌面程序，**未实机验证你本机 4.3.23 编辑器导入**，也未生成原生 `.spine` 文件。GIF 是项目自身渲染的动作预览，不是 Spine 桌面截图；它不能代替导入后检查。原画没有拆分下颌，喷吐通过头颈动作和口部效果表现，没有伪造独立张嘴结构。

普通浏览器双击 `preview.html` 可看 GIF；若浏览器管理策略禁止 `file://`，可以跳过预览直接导入 Spine，或在素材目录运行 `py -3.12 -m http.server 8001 --bind 127.0.0.1` 后访问 `http://127.0.0.1:8001/preview.html`。角色六个动作都有约 128 px 高的手机尺寸预览；所有手机对照循环播放方便观察，但死亡在游戏内仍应单次播放。

## 开发重建（可选，需要完整仓库）

本地导入 Spine 不需要 Python。只有修改生成规则/运行测试才需要完整仓库和 `requirements.txt`：

```bat
.venv\Scripts\python.exe tools\build_bsq_spine.py
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

`tools/build_bsq_spine.py` 是本角色的生成脚本；`rig-config.json` 中的骨骼位置仍为原始 PS 的 X 向右、Y 向上的坐标。脚本会覆盖生成的 JSON、特效、预览，先保留自己手工修改的 Spine 工程。

官方运行库检查仅用于开发验证，需要 Node.js 和单独安装的运行库，不是使用动画包的条件：

```bat
npm install --no-save --package-lock=false @esotericsoftware/spine-core@4.3.13
node tests/validate_bsq43.mjs
```

修改 JSON 后应重跑此命令，报告包含文件哈希；Python 测试会拒绝过期报告。
