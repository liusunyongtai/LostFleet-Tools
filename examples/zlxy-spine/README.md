# ZLXY 重甲枪兵 · Spine PRO 4.3.23

保留上传的 9 张角色透明 PNG，新增可编辑骨骼、加权网格、六个动作、枪口火花与表面暖光，以及独立飞行子弹。采用夸张的预备、冲击、回弹与延迟跟随；移动原地循环。不是自动补绘遮挡部位。

## 导入本地 Spine

1. 完整解压 ZIP，保持 JSON 和 `images/` 的相对位置，不要只下载 JSON。
2. 在 **Spine PRO 4.3.23** 中选择“导入数据”，导入 **`zlxy-4.3.json`**，缩放填写 **1**。图片路径为 `./images/`。
3. 保存为自己的 `.spine` 工程。JSON 是可编辑导入数据，不是伪造的 `.spine` 二进制文件。
4. 新建另一个工程，以缩放 **1** 导入 **`flying-bullet-4.3.json`**。角色和子弹是两个独立骨架。
5. 动画模式中选择动作；仅为 `stand`、`move` 和子弹 `bullet` 打开循环。攻击与受击播放一次，死亡保持最后一帧。

需要 Professional 的加权网格功能。原图尺寸、图层位置、透明度不变，双臂、双腿和软管采用连续网格绑定；武器、头盔和背包保持刚性。近战时支撑手主动松开，举枪前砸后重新握持，避免两只手被强行拉长。

| 动作 | 时长 | 内容 |
| --- | --- | --- |
| `stand` | 2.4 秒 | 呼吸起伏、头盔与背包延迟跟随 |
| `move` | 1.0 秒 | 原地交替迈步、抬脚、腰身起伏，首尾循环 |
| `hit` | 0.5 秒 | 躯干后震、头部延迟与回弹 |
| `dead` | 1.6 秒 | 屈膝卸力、侧倒、触地回弹，最终保持 |
| `attack_1` | 1.2 秒 | 举枪蓄力、向前下砸、回弹与复位 |
| `attack_2` | 1.2 秒 | 瞄准、开枪、枪口上跳、后坐力与恢复 |
| 子弹 `bullet` | 0.4 秒 | 原地循环，金属弹头刚性、尾焰摆动伸缩 |

## 游戏接入与特效

角色原始朝向为左。`attack_1` 在 **0.6 秒**发出 `melee_hit` 事件，事件字符串指向 `melee_tip` 骨骼。`attack_2` 在 **0.4 秒**发出 `shoot` 事件，字符串指向 `projectile_spawn`。不要在游戏里重复定时生成子弹。

收到 `shoot` 事件时，把子弹实例放在角色 `projectile_spawn` 的世界位置，朝向按武器变化。该骨骼位于枪口前方 90 像素，对应子弹刚性弹头距子弹根约 90 像素的左向偏移，初生时弹头在枪口前方、尾焰在后。参考枪口方向可用 `muzzle` 的世界旋转，子弹美术本身向左；若运行时用“局部 +X 为前方”，应先扣除素材左向的 180°，再应用旋转，避免二次反转。角色整体镜像时也同步镜像子弹。

**子弹的根骨骼始终不移动**，`bullet` 是飞行中尾焰的原地循环，实际平移、速度、碰撞、伤害和销毁由游戏控制。人物 `move` 的根骨骼同样不发生水平位移。攻击中的小幅身体前送属于身体动作，不会推进角色根节点。

枪口使用三帧大火花与柔和光晕；枪身、双臂、头盔、躯干各有贴合原网格的暖色加法光照遮罩，并按原遮挡顺序排列。0.4 秒闪亮后渐隐，随后隐藏。它们是可导出的 **2D 加法叠加特效**，不是引擎实时动态光源。运行时需支持 Spine 的 additive 混合；若使用 PMA 图集，导出与渲染混合设置要一致。

## 文件与预览

- `preview.html`：六动作普通/手机尺寸 GIF、子弹循环、关键姿势与绑骨图。GIF 是独立软件渲染，**不是 Spine 桌面截图**。攻击 GIF 为便于查看重复演示，不代表游戏中自动连发。
- `images/*.png`：9 张原始 PNG；`source/image-sha256.json` 用于核对，原图字节未变。
- `images/fx/`：新增火花、光照遮罩与透明子弹；子弹是此次新增 AI 生成美术，来源和 SHA256 在 `source/projectile-image.json`。
- `source/photoshop.json`：保留源位置与图层，规范化图片相对路径。
- `rig-config.json`：枢轴、握持点、落脚点、武器与事件配置。
- `runtime-validation.json`、`bullet-runtime-validation.json`：官方运行库逐帧检查记录。

可直接用普通浏览器打开 `preview.html`。若本地限制文件资源，在此目录运行 `python -m http.server 8000`，再打开 `http://127.0.0.1:8000/preview.html`。云端实际验证使用临时 HTTP 服务与 Chromium，未将 `file://` 打开方式记为已测试。
